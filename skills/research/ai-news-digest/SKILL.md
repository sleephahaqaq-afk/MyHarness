# AI 资讯采集规则

## 采集入口（先读这个）

**第一步永远是
`read_skill_resource("builtin/research/ai-news-digest/SKILL.md", "resources/sources.md")`**。
那里是已验证的 feed/API 清单（arXiv API、Hacker News Algolia、三家厂商新闻室），
`web_fetch` 直接抓就是结构化数据，自带日期与 URL。`web_search` 是补充手段，不是首选——
它每次都是一整次模型调用，而且只给二手摘要。

## 来源分级

| 级别 | 例子 | 采信方式 |
|---|---|---|
| 一手 | 厂商官方博客、GitHub Release、模型卡、arXiv 论文、官方 API 文档 | 可直接引用，需记录发布日期 |
| 准一手 | 作者本人推文/博客、官方直播回放、会议 slides | 可引用，标注"作者声明" |
| 二手 | 科技媒体报道、聚合站、 newsletter | 需交叉验证，优先找一手原文 |
| 传闻 | "据知情人士"、未署名爆料、截图 | 只能进 `unverified`，不得写成事实 |

## 时间判定

- **发布日期**取一手页面的发布日，不取转载日、不取搜索结果里的"最新"标记；
- 无日期 → 进 `unverified`；
- 只有"最近/近期"这类模糊表述 → 视为无日期；
- 版本发布时间与**实际可用时间**要区分（预告 ≠ 已发布 ≠ 已开放 API）。

## 去重与合并

- 同一事件的多篇报道合并成一条，取信息量最大的来源做主来源，其余列入 sources；
- 同一模型的多个版本，按版本号合并成一条，写清版本差异；
- 转载稿不算独立来源（正文高度重合即为转载）。

## 影响面排序

按以下优先级排序，同级别按时间倒序：

1. 能力边界变化（新模态、新规模、新 benchmark SOTA）
2. 可获得性变化（开源 / 开放 API / 降价 / 区域限制）
3. 生态影响（框架支持、工具链、兼容性）
4. 组织与资本动作（融资、并购、人事）
5. 政策与合规

## 反幻觉清单

写之前逐条自查：

- [ ] 每条都有 URL 和日期？
- [ ] 版本号/参数规模是页面原文，不是推测？
- [ ] 有没有把"预告"写成"已发布"？
- [ ] 有没有把旧闻当新闻（检查年份）？
- [ ] 冲突数据是否两边都列了？

任一条不满足，就降级到 `unverified` 或补检索。
